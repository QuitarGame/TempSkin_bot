# Skin Order Bot

Телеграм-бот для бесплатного заказа отрисовки скинов. Три роли: пользователь, художник, администратор. Хранилище — Firebase (Firestore).

## Возможности

- **Роли не эксклюзивны**: у одного пользователя может быть сразу несколько ролей — заказчик (есть у всех по умолчанию), художник, администратор. Меню в боте показывает разделы под все роли, которые есть у пользователя.
- **Пользователь**: заполняет короткую анкету (пол персонажа + пожелания + свободное описание + референсы-картинки), отслеживает свои заказы в личном кабинете.
- **Художник**: сразу получает уведомление о каждом новом заказе (рассылка всем художникам одновременно). Может принять заказ («кто первый — тот и берёт») или отклонить. Как только заказ принят одним художником, у остальных карточка автоматически меняется на «уже взят другим художником», и принять его больше нельзя. Когда работа готова — художник жмёт «🏁 Готово», может прикрепить один или несколько файлов (фото/документы) с итоговым скином, и они прямо через бота уходят заказчику.
- **Администратор**: назначает роль «художник» или «администратор» любому пользователю по username (в том числе себе) — это единственный способ появления художников/админов, никакой отдельной «привязки» заказа к конкретному человеку админ не делает. Также видит заказы по статусам и списки художников/админов.

### Статус-флоу заказа

`новый` → (рассылается всем художникам) → `на проверке` → (кто-то принял) → `в работе` → `готово`

Заказ получает статус `отклонено` только тогда, когда **все** художники, которым он был разослан, отклонили его. Если в момент создания заказа художников ещё нет вообще, заказ остаётся в статусе `новый` и автоматически уходит всем сразу, как только администратор назначит первого художника.

### О производительности

Библиотека `firebase-admin` синхронная — каждый запрос к Firestore блокирует поток, в котором он выполняется. Чтобы бот не «зависал» при каждом обращении к базе (и не подвисал одновременно для всех пользователей), все функции в `db.py` выполняют реальную работу в отдельном потоке через `asyncio.to_thread`, а наружу отдают `async`-обёртки — в хендлерах просто пишется `await db.что-то(...)`.

## Установка (локально)

1. Установи зависимости:
   ```
   pip install -r requirements.txt
   ```

2. Создай бота через [@BotFather](https://t.me/BotFather), получи токен.

3. Создай проект в [Firebase Console](https://console.firebase.google.com/) → включи Firestore Database (режим "production" или "test", как удобно на старте) → Project Settings → Service accounts → **Generate new private key**. Сохрани скачанный JSON-файл как `firebase-key.json` рядом с ботом. **Этот файл никогда не должен попасть в git** — он уже добавлен в `.gitignore`.

4. Узнай свой Telegram ID (например, через [@userinfobot](https://t.me/userinfobot)) — он понадобится, чтобы автоматически получить роль администратора при первом запуске бота.

5. Скопируй `.env.example` в `.env` (или просто задай переменные окружения в терминале) и заполни:
   ```bash
   export BOT_TOKEN="токен_от_botfather"
   export FIREBASE_CREDENTIALS_PATH="firebase-key.json"
   export ROOT_ADMIN_ID="твой_telegram_id"
   ```

6. Запусти бота:
   ```
   python bot.py
   ```

7. Напиши боту `/start` со своего аккаунта — ты автоматически получишь роль администратора. Дальше через «⚙️ Кабинет администратора» → «➕ Назначить художника» / «👑 Назначить администратора» можно выдавать роли по @username (в том числе себе).

## Деплой на Railway через GitHub

Файл с ключом Firebase (`firebase-key.json`) — это полный доступ к твоей базе данных, поэтому **его нельзя коммитить в GitHub**, даже в приватный репозиторий. Вместо файла на Railway ключ передаётся через переменную окружения `FIREBASE_CREDENTIALS_JSON` — бот уже умеет читать его оттуда (см. `config.py` / `db.py`).

**Шаги:**

1. Убедись, что `firebase-key.json` и `.env` физически не попадают в git — они уже в `.gitignore`. Если ты когда-либо уже коммитил `firebase-key.json` — этого недостаточно просто удалить и закоммитить заново, ключ останется в истории git. В таком случае зайди в Firebase Console → Project Settings → Service accounts → удали старый ключ и создай новый (это отзовёт доступ по старому).

2. Запушь проект в GitHub как обычно:
   ```
   git init
   git add .
   git commit -m "skin order bot"
   git remote add origin <ссылка на твой репозиторий>
   git push -u origin main
   ```

3. На [railway.com](https://railway.com) создай новый проект → **Deploy from GitHub repo** → выбери репозиторий. Railway сам определит `Procfile` и запустит `python bot.py` (не забудь, что там указан тип процесса `worker`, а не `web` — это нормально, у бота нет веб-сервера, и Railway это поддерживает).

4. В Railway зайди в **Settings → Variables** этого сервиса и добавь:
   - `BOT_TOKEN` — токен бота
   - `ROOT_ADMIN_ID` — твой Telegram ID
   - `FIREBASE_CREDENTIALS_JSON` — содержимое твоего `firebase-key.json` **целиком, одной строкой**. Проще всего: открой файл, скопируй весь JSON (от `{` до `}`) и вставь как значение переменной — Railway нормально хранит длинные строки, переносы строк внутри ключа `private_key` останутся частью JSON и распарсятся корректно.

5. Railway пересоберёт и запустит сервис. В логах должно появиться, что polling стартовал без ошибок. Проверь ботом `/start`.

**Важно:** если у тебя ещё установлена переменная `FIREBASE_CREDENTIALS_PATH` (например, скопировал с локальной машины) — не страшно, `FIREBASE_CREDENTIALS_JSON` имеет приоритет, если она задана.

## Структура проекта

```
skinbot/
├── bot.py              # точка входа
├── config.py            # токены, статусы, роли
├── db.py                # обёртка над Firestore
├── states.py            # FSM-состояния (анкета заказа и т.д.)
├── keyboards.py          # клавиатуры
├── handlers/
│   ├── common.py         # /start, общее меню, отмена
│   ├── user.py           # анкета заказа, «Мои заказы»
│   ├── artist.py          # кабинет художника, принять/отклонить/готово
│   └── admin.py           # кабинет администратора, назначение художников
└── requirements.txt
```

## Важные заметки

- Firestore используется вместо SQLite/Postgres, как вы попросили — все запросы идут через `db.py`, при желании легко заменить на другую БД, не трогая хендлеры.
- Пользователь должен хотя бы раз написать боту `/start`, прежде чем администратор сможет назначить ему роль по username (это ограничение Telegram API — бот не может искать людей "вслепую").
- Оплата и любые платежи в проекте не предусмотрены — сервис полностью бесплатный, как и требовалось.
- Для продакшена рекомендуется задать правила безопасности Firestore (Security Rules), так как в этом MVP доступ к базе идёт напрямую через service account с полными правами.
